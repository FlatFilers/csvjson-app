## Path B — full setup from a fresh clone

Prerequisites: Debian sandbox with sudo. No package.json/composer.json — nothing to `npm install` or `composer install`.

1. **Install runtime:**
   `sudo apt-get update && sudo DEBIAN_FRONTEND=noninteractive apt-get install -y php-cli php-mysql php-curl php-mbstring php-xml mariadb-server`
   (Add `chromium` only if you need browser automation.)
2. **Start DB:** `sudo service mariadb start`
3. **Create database + user + table** (no migrations exist in this repo; schema inferred from `Csv2json::instrument()`):
   ```sql
   CREATE DATABASE IF NOT EXISTS csvjson CHARACTER SET utf8 COLLATE utf8_general_ci;
   CREATE USER IF NOT EXISTS 'csvjson'@'localhost' IDENTIFIED BY 'csvjson';
   GRANT ALL PRIVILEGES ON csvjson.* TO 'csvjson'@'localhost';
   FLUSH PRIVILEGES;
   CREATE TABLE IF NOT EXISTS csvjson.csv (
     id INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
     `columns` TEXT NOT NULL,
     num_rows INT NOT NULL DEFAULT 0,
     created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
   ) ENGINE=InnoDB DEFAULT CHARSET=utf8;
   ```
4. **Create `data/` at repo root** (gitignored; local permalink storage): `mkdir -p data`
5. **Create `application/config/development/` overrides** (directory is gitignored; CI loads `config/<ENVIRONMENT>/*.php` in preference to the base files):
   - `config.php` — copy of `application/config/config.php` with `$config['base_url'] = 'http://127.0.0.1:8080/';` and, right after the BASEPATH guard, `error_reporting(E_ALL & ~E_DEPRECATED & ~E_STRICT);` (CI 2.1.4 emits ~44 deprecation notices per request on PHP 8 — without this, error divs precede the doctype and pages render in quirks mode)
   - `database.php` — copy of the base file with `'username' => 'csvjson', 'password' => 'csvjson'`
   - `aws_s3.php` — `$config['aws_s3'] = array('supported' => false);` (keeps `AWS_S3_URL` undefined so permalinks use disk; also avoids "Undefined array key" warnings from the base file's `$_ENV` reads)
6. **Create `router.php` at repo root** (untracked) — the PHP built-in server needs it to serve static assets and mirror `.htaccess` (block `system/`, `application/`, `.git`, `README.md`; redirect `/dataclean` → `/datajanitor`; route the rest to `index.php` with `$_SERVER['PATH_INFO']` set). Copy it from this snapshot or reconstruct from that spec.
7. **Start:** `nohup php -S 127.0.0.1:8080 router.php > /tmp/php-server.log 2>&1 &`

## Gotchas (do not "fix" these in passing)

- `application/libraries/s3.php:2582` and `system/libraries/Profiler.php:70` are PHP 8 **parse errors** (curly-brace string offsets). They never load in local dev (S3 off, profiler off). If you must touch S3 mode, port those files to PHP 8 first.
- `index.php` sets `ENVIRONMENT=production` when `SERVER_NAME` contains `csvjson.com`; local dev always gets `development`, which loads unminified assets from `js/src/` per `application/config/assets.php`.
- Production bundles (`js/*.min.js`, `css/csvjson.css`) are generated by visiting `/build` and are committed to git.
- No test suite, no linter, no CI config in this repo. `php -l` is the only static check available.
- File upload (`/csv2json/upload`) is a PHP 5 era path (`csvjson_helper.php` expects `$_FILES['file']`); paste CSV into the textarea instead.
